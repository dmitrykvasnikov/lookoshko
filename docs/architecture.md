# Предварительная архитектура

Это предложение, а не перечень уже реализованных компонентов.

## Android

Предлагается Kotlin + Jetpack Compose. Интерфейс отделяется от загрузки данных через слой репозиториев; состояние экранов хранится в ViewModel. Для локальной базы после появления постоянного хранения предлагается Room.

Первая сборка читает подготовленные данные из ресурсов приложения и ищет объекты локально, без внешнего геокодера или Places API. На этапе общей базы подключается сетевой источник, при этом экраны продолжают работать через тот же интерфейс репозитория.

Источники технических ориентиров:
- https://developer.android.com/topic/architecture/recommendations
- https://developer.android.com/topic/architecture/data-layer/offline-first
- https://developer.android.com/develop/sensors-and-location/location/permissions

Версии SDK и библиотек фиксируем при создании собираемого проекта после проверки совместимости.

## Карта и местоположение

Для технического прототипа принято использовать MapLibre Native как движок отображения и публичный сервис OpenFreeMap как источник векторных тайлов на основе OpenStreetMap. Прототип не требует Google Maps SDK, Google API-ключа или включённого биллинга.

Источник стиля и тайлов инкапсулируется в отдельной конфигурации и не попадает в UI-модели. Это позволит заменить OpenFreeMap другим совместимым поставщиком или собственным источником без переделки экранов. Требуемая атрибуция OpenFreeMap, OpenMapTiles и OpenStreetMap показывается на карте постоянно.

Публичные серверы `tile.openstreetmap.org` не используются приложением как бесплатный производственный источник и не применяются для предварительного скачивания. У OpenFreeMap нет SLA, поэтому при недоступности карты пользователь сохраняет доступ к локальному списку, карточкам и текстам.

Местоположение получается через системные API Android только при открытом приложении. Для технического прототипа не требуется Google Play Services. Геолокация используется для сортировки и расстояний, ручной просмотр доступен всегда. При низкой точности не обещаем определение конкретного здания. Точные координаты объектов проверяем отдельно от пользовательских координат.

## Аудио

Для технического прототипа принята системная озвучка Android без облачного сервиса. Русский голос и работа без сети зависят от установленного движка и его данных; это нужно проверить на целевых телефонах. При недоступности озвучки остаётся текст и понятное объяснение.

Поведение паузы / продолжения и воспроизведения при блокировке проверяем до фиксации реализации. При необходимости стабильного одинакового голоса можно позже перейти на заранее подготовленные аудиофайлы.

## Сервер

В демонстрационной сборке сервера нет: два объекта, поиск и медиа находятся в ресурсах приложения. Сервер появляется только после успешной полевой проверки, на этапе общей базы и пользовательских публикаций. Нужны API, база данных, хранение фотографий, вход пользователей и кабинет модератора. Конкретный поставщик, бесплатный тариф и размещение не выбраны. Доступ к неопубликованному контенту, права редакторов и уникальность голосов проверяются на сервере.

## Сущности

| Сущность | Основные данные |
| --- | --- |
| Place | ID, название, альтернативные названия, координаты, адрес, тип, фото, статус публикации |
| Story | ID, место, автор, заголовок, краткий и полный текст, язык, источники, статус, версия, статус проверки фактов |
| Media | ID, связанный объект, тип, расположение файла, авторство, условия использования |
| Vote | Пользователь, рассказ, значение, дата изменения; уникальная пара пользователь + рассказ |
| User | ID, отображаемое имя, роль |
| Report | Автор жалобы, место или рассказ, причина, статус рассмотрения |
| Revision | Рассказ, версия текста, редактор, дата, причина изменения |

Аудио связывается с версией рассказа, чтобы после правки текста не проигрывать устаревшее описание.

## Публикация и модерация

Рабочая цепочка: черновик → на проверке → опубликовано / на доработке / отклонено. Для уже опубликованного рассказа правка создаёт новую редакцию; порядок её проверки нужно определить. Опубликованный материал может быть скрыт модератором с сохранением истории.

## Рейтинг

Стартовое предложение: «Полезно / Не полезно». Один голос аккаунта на рассказ с возможностью изменения. Конкретную формулу выбираем перед этапом рейтингов; она должна учитывать объём оценок и давать новым рассказам возможность получить голоса. Рейтинг не является проверкой исторической точности.
